## What This Repository Is

This is a NixOS infrastructure monorepo for a personal homelab and two personal machines
(desktop and laptop). It declares every machine, every service, every user, and every
network policy as code. Nothing is configured manually. Everything is reproducible.

The monorepo is intentionally public. The security posture is designed to be sound
even with full configuration visibility. Secrets are encrypted via sops-nix. State is
stored in a private remote backend. Obscurity is not a layer of defense here.

## The mkHost Pattern

Every host is built by `lib/mkHost.nix` which accepts a `tags` attribute set and
composes the correct module set. A host declares only its tags — no direct module imports.

```nix
# hosts/desktop/default.nix
{ lib, ... }:
{
  imports = [ (import ../../lib/mkHost.nix { inherit lib; }) ./hardware.nix ];

  tags = {
    laptop        = false;
    gaming        = true;
    amdGpu        = true;
    intelGpu      = false;
    multiMonitor  = true;
    hdr           = true;
  };

  networking.hostName = "desktop";
}
```

`mkHost.nix` reads `config.tags` and imports the appropriate modules:

```
tags.gaming    = true  → modules/gaming/*
tags.amdGpu    = true  → modules/hardware/gpu/amd.nix
tags.intelGpu  = true  → modules/hardware/gpu/intel.nix
tags.laptop    = true  → modules/laptop/*
tags.hdr       = true  → modules/hardware/displays/hdr.nix
```

`modules/core/*` is always imported regardless of tags.

## Naming Conventions

### NixOS modules
- Module files use kebab-case: `ssh-recording.nix`, `auto-cpufreq.nix`
- Options added by custom modules are namespaced: `my.gaming.enable`, `my.ssh-recording.scope`
- Never use `environment.systemPackages` in core modules — use module-specific options

### Nix expressions
- Attribute sets: camelCase keys
- File-level arguments: destructured `{ pkgs, lib, config, ... }:`
- Never use `with pkgs;` at the top level of a module — always qualify package names

### OpenTofu
- Resource names: snake_case matching the FreeIPA/Authentik object name
- Variable files: `vars.tfvars` per module directory
- Never hardcode IPs or hostnames — use variables or data sources

### Secrets
- sops-nix secret paths follow: `/run/secrets/<service>/<key>`
- Example: `/run/secrets/cloudflare/api_token`, `/run/secrets/vaultwarden/admin_token`
- Secret names in `secrets.yaml` match the path structure: `cloudflare.api_token`

### Git branches
- Feature branches: `feat/<short-description>`
- Fix branches: `fix/<short-description>`
- Hotfix branches: `hotfix/<short-description>`
- Never push directly to `main` — always PR

## The Feature Tag → Module Composition System

When adding a new module, follow this checklist:

1. Create the module file in the correct `modules/` subdirectory
2. Add a `lib.mkOption` boolean tag if the module is host-conditional
3. Add the tag import condition to `lib/mkHost.nix`
4. Add the tag to the Host Tags Reference table in this file
5. Add the tag to the relevant host `default.nix`
6. Verify with `nix eval .#nixosConfigurations.<hostname>.config.system.build.toplevel`

## Identity and Authentication Architecture

```
FreeIPA (VM1)
  ├── LDAP directory: source of truth for all users, groups, hosts
  ├── Kerberos KDC: issues TGTs for all enrolled users
  ├── BIND DNS: authoritative for internal.tongatime.us
  ├── Dogtag PKI: internal CA for Kerberos KDC and LDAP TLS
  └── HBAC engine: controls which users can log into which hosts

SSSD (every enrolled host)
  ├── Authenticates against FreeIPA Kerberos
  ├── Resolves user/group info from FreeIPA LDAP
  ├── Caches credentials (cache_credentials = true — mandatory on laptop)
  ├── Distributes SSH public keys from FreeIPA
  ├── Enforces sudo rules declared in FreeIPA
  └── Invokes tlog-rec-session for all authenticated terminal sessions

Authentik (VM2)
  ├── OIDC/SAML provider for all web applications
  ├── Syncs user list from FreeIPA LDAP (read-only)
  └── MFA: WebAuthn/passkey preferred, TOTP fallback

tlog (every enrolled host, via SSSD)
  └── Records all terminal sessions to journald as structured JSON
```

**Login flow (OS login):**
SDDM → PAM → SSSD → Kerberos AS-REQ → FreeIPA TGT → HBAC check → tlog session wrap → KDE

**Login flow (web app):**
Browser → Authentik → FreeIPA LDAP user lookup → OIDC token → application

**SSH flow:**
ssh client → ProxyJump VM1 → SSSD auth → tlog records → target VM → SSSD auth → tlog records

## Network Architecture

```
VLAN 10 — Management:  router, switch, iDRAC, hypervisor BMC
VLAN 20 — Infrastructure: VM1, VM2, VM3 (internal.tongatime.us services)
VLAN 30 — Trusted:     desktop, laptop, trusted personal devices
VLAN 40 — IoT:         smart home, printers, embedded devices
VLAN 50 — Guest:       visitor devices, internet only
VLAN 60 — DMZ:         VM4, public-facing game servers
```

Headscale mesh overlays VLANs. All personal machines and VMs are mesh peers.
ACLs: tag:admin (personal machines) → any. tag:dmz-proxy (Oracle VPS) → tag:dmz-server (VM4) only.
Exception: Oracle VPS → VM1 on port 443 (Headscale coordination endpoint only).

## Service Deployment Conventions

### Podman containers on VMs
All services run as rootless Podman containers declared as NixOS quadlet units.
No service is installed bare-metal except: SSSD, Kerberos client daemons, Headscale (VM1).

Container definition pattern:
```nix
# In the VM's NixOS config
virtualisation.oci-containers.containers."service-name" = {
  image = "registry/image@sha256:digest";  # always digest-pinned
  environment = { ... };
  volumes = [ "/persist/service-data:/data" ];
  ports = [ "127.0.0.1:8080:8080" ];  # bind to loopback; Caddy proxies externally
};
```

Containers that need to spawn other containers use a Podman socket proxy.
Never bind-mount the raw Podman socket into a container.

### Caddy reverse proxy
Every service is accessed via Caddy with a Let's Encrypt cert from DNS-01 ACME.
Caddy config is declared in NixOS, not in a Caddyfile written by hand.
All internal services bind to loopback; Caddy terminates TLS and proxies.

Pattern:
```
auth.internal.tongatime.us → 127.0.0.1:9000 (Authentik)
git.internal.tongatime.us  → 127.0.0.1:3000 (Gitea)
```

### Secrets injection
Secrets are never in the Nix store. They are mounted by sops-nix at activation time.
Reference in container definition:
```nix
environmentFiles = [ "/run/secrets/service/env-file" ];
```

## Deployment

```
git push → Gitea Actions runner →
  nix flake check (lint + eval) →
  nix build .#nixosConfigurations.*.config.system.build.toplevel →
  deploy-rs push to each host →
  attic cache push of build results
```

Deployment strategy by host:
- VM1: blue-green only. Previous generation must be bootable as rollback.
- VM2: blue-green for stateful services (Vaultwarden, Gitea, Authentik). Rolling for stateless.
- VM3: rolling acceptable.
- VM4: any strategy.
- Desktop/Laptop: blue-green (NixOS generations).

Manual deploy command (emergency):
```bash
nixos-rebuild switch --flake .#<hostname> --target-host user@host --use-remote-sudo
```

## Adding a New Service (Checklist)

1. Create NixOS quadlet unit in the appropriate VM's config or a new module
2. Add Caddy virtual host: `<service>.internal.tongatime.us` or `<service>.tongatime.us`
3. Add FreeIPA DNS A record via OpenTofu (`tofu/dns/`)
4. Add Authentik OIDC client via OpenTofu (`tofu/authentik/`) if the service has a web UI
5. Add Prometheus scrape target in VM3 config
6. Add Loki pipeline stage for this service's log format
7. Add sops-nix secret entries for any credentials
8. Add to PORT_REFERENCE.md
9. Add to the tool registry in PROJECT_RULES.md Appendix
10. Update Structurizr DSL (`docs/architecture/workspace.dsl`) with the new container
11. Commit, PR, review, merge

## Adding a New User (Checklist)

1. Add `freeipa_user` resource to `tofu/identity/users.tf`
2. Add user to appropriate FreeIPA groups in `tofu/identity/groups.tf`
3. Add HBAC rule or extend existing rule in `tofu/identity/hbac.tf`
4. Add sudo rule if needed in `tofu/identity/sudo.tf`
5. Run `tofu apply` in `tofu/identity/`
6. User propagates automatically to Authentik via LDAP sync

## Sops-nix Key Structure

Each host has an age key at `/etc/sops-age-key`.
The `.sops.yaml` declares which hosts can decrypt which secrets.

```yaml
# secrets/.sops.yaml
keys:
  - &desktop age1...
  - &laptop age1...
  - &vm1 age1...
  - &vm2 age1...
  - &vm3 age1...

creation_rules:
  - path_regex: secrets/cloudflare\.yaml$
    key_groups:
      - age: [*vm1, *vm2]  # only VMs that need Cloudflare API access
  - path_regex: secrets/vaultwarden\.yaml$
    key_groups:
      - age: [*vm2]
  - path_regex: secrets/common\.yaml$
    key_groups:
      - age: [*desktop, *laptop, *vm1, *vm2, *vm3]
```

## What Claude Code Should NOT Do In This Repo

- Never write plaintext secrets anywhere — use sops-nix references
- Never use `environment.systemPackages` to install packages that have proper NixOS module options
- Never add `allowUnfree = true` — use `allowUnfreePredicate` with explicit package names
- Never create a Caddyfile by hand — declare reverse proxy in NixOS
- Never write a Dockerfile or docker-compose.yml — use Podman quadlet units
- Never run `nixos-rebuild switch` without verifying `nix flake check` passes first
- Never edit `flake.lock` manually — use `nix flake update` or Renovate PRs
- Never commit to `main` directly — always use a branch and PR
- Never store OpenTofu state in the repository
